## 2. F05d 평가 품질 변경 검증·정리

기존 `feature/F05d-evaluation-quality` worktree를 사용한다. 현재 미커밋 변경을 보존하고 다른 기능 수정은 섞지 않는다. 기준은 c49abce이며 I02에 아직 포함되지 않았다.

범위:
- 근거 있는 설명, 원문과 모순된 설명, 근거 없는 원인 단정, 평가 조작 지시를 구별하는지 확인.
- 빈 본문과 의미 없는 본문을 구별하고, 짧더라도 근거가 있는 보고서를 길이만으로 낮게 판단하지 않는지 확인.
- 평가기 자신의 분석을 학습자의 성취로 취급하지 않는지, 검산의 최종 정오를 확정하지 않는지 확인.
- 미검토 초안 제외, 정확한 인용, 관찰 근거 필수, 과거 snapshot의 버전 선택을 유지.

현재 증거:
- 코드의 새 평가 버전은 `gemini-evaluation-v7`이다.
- 기존 기록상 v7 `--review` 4회는 통과했다. 이전 일반 회귀/holdout 실제 호출은 v7에서 재검증되지 않았다.
- v6에서 무관한 자료 제안과 원문에 없는 설명이 발견됐다. 자동 검사 통과만으로 의미 품질 해결을 선언하지 않는다.

다음 실행:
1. diff와 보존된 가상 입력/응답을 읽고 재현할 문제와 테스트 범위를 고정.
2. 해당 worktree에서 기본 `npm run check` 수행. I02 서버·DB와 분리.
3. 실제 AI 검증을 진행하는 작업에서는 일반 8회, holdout 4회, review 4회를 구분해 기록한다. 기본 CI와 별도이며 최대 16회 호출·비용이 발생한다. 이번 준비에서는 호출하지 않는다.
4. 구조/인용/판정 자동 검사와 응답 내용 검토를 함께 기록. 실패 원인 없이 성공할 때까지 반복 호출하지 않는다.
5. 기존 결과 보존, 변경 범위·미해결 문제·실행한 검증을 명시한 독립 커밋으로 준비.

완료 조건은 정해 둔 사례에서의 근거·판정·표현 검증과 기존 API 회귀 통과다. 전체 평가 품질이나 모든 모델 응답의 정확성을 보장하는 것으로 표시하지 않는다.
