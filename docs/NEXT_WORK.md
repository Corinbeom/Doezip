# 다음 작업 — P06 이후

기준일 2026-09-17. 현재 통합 기능과 과제 콘텐츠 v0.2 이후의 우선순위다. 완료 여부는 각 기능 문서와 배포 기록의 실제 검증 결과를 기준으로 판단한다.

2026-09-17에 최신 `main`을 공개 웹과 API에 반영하고 기존 Google 계정 재로그인, 콘텐츠 v0.2 시작, 실제 Gemini 대화를 확인했다. 상세 결과와 최초 가입 미실행 범위는 [D01 배포 기록](D01_DEPLOYMENT.md)을 따른다.

## 1. 공개 사용자 관찰

- 사용하지 않은 Google 계정으로 최초 가입부터 시작하는 흐름을 한 번 확인한다.
- 처음 방문한 사용자가 로그인, 과제 선택, AI 질문, 결과물 작성, 검증, 직접 설명, 피드백까지 도움 없이 완료하는지 관찰한다.
- 막힌 위치, 소요 시간, AI 제안을 그대로 적용한 지점, 이해하지 못한 용어를 기록한다.
- 결과물 내용과 비밀값을 이슈·스크린샷에 그대로 옮기지 않는다.

## 2. 과제 콘텐츠 확장

- v0.2 한 세트의 실제 사용 결과를 본 뒤 난도와 직무 맥락이 다른 후속 보고서·구현 과제를 추가한다.
- 훈련과 모의 전형은 힌트 유무만이 아니라 자료 범위와 제한 조건도 구분한다.
- 공개 테스트가 해법 전체를 드러내지 않도록 독립 서버 검증의 범위와 신뢰 경계를 먼저 설계한다.

## 3. 피드백 의미 품질

- 요청의 구체성, AI 제안의 비교·거절, 원자료 대조, 실행 근거, 수정 이유가 실제 기록에 근거해 평가되는지 사례별로 검토한다.
- 실제 Gemini 회귀 검사는 기본 CI와 분리하고 호출 수·모델·응답 검토 결과를 기록한다.
- 관찰하지 못한 역량을 낮은 점수로 표현하지 않고, 비공개 정답이나 평가 내부 판단을 브라우저에 노출하지 않는다.

## 4. 공개 배포 운영

- 최신 `main`의 웹·API·DB health, CORS, 보호 경로, 기존 Google 계정 재로그인과 v0.2 실제 AI 대화는 확인했다. 새 계정 최초 가입과 v0.2 전체 제출·평가는 다음 사용자 검증에 포함한다.
- Vercel 프로젝트의 GitHub 자동 배포 연결 여부를 결정한다. 현재 Production은 팀 범위를 명시한 CLI 배포 방식이다.
- Render 무료 인스턴스의 cold start와 PostgreSQL 만료 전에 유료 전환·백업·DB 17 재생성 여부를 결정한다.
- 오류율과 지연을 확인할 최소 로그·모니터링을 정하고 사용자 원문·토큰·키를 기록하지 않는다.

## 5. 보류 범위

- 전체 ERD 22개와 대량 seed
- 범용 저장소 연결·쉘 실행·클라우드 개발 환경
- 숨은 서버 채점과 여러 언어 실행기
- 캐릭터·일러스트 등 시각 자산의 최종 제작

보류 범위는 사용자 관찰로 필요성이 확인되기 전까지 현재 공개 흐름과 섞지 않는다.
