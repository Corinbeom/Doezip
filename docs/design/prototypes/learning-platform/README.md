# 되짚 — 학습 플랫폼 디자인 시안

상태: **승인 전 디자인 시안 v0.1** · 작성일: 2026-09-07

가상 데이터와 모의 AI 응답을 사용하는 독립 HTML 프로토타입이다.

문제를 선택해 풀고, 근거를 확인한 뒤 판단을 수정하는 전체 학습 흐름을 검토하기 위한 클릭형 프로토타입이다. 제품 기능 구현 완료를 의미하지 않는다.

## 열어보기

`index.html`을 브라우저에서 열 수 있다. 일관된 브라우저 저장 동작을 위해 로컬 서버 사용을 권장한다. 별도 패키지 설치나 빌드가 필요하지 않다.

저장소 루트에서:

```sh
python3 -m http.server 4387 --bind 127.0.0.1 --directory docs/design/prototypes/learning-platform
```

그다음 [로컬 미리보기](http://127.0.0.1:4387/)를 연다. 다른 컴퓨터에서 이 주소를 열려면 그 컴퓨터에서도 시안 폴더와 서버를 준비해야 한다. 이미 4387 포트를 사용 중이면 다른 포트를 지정한다. 종료는 서버를 실행한 터미널에서 `Ctrl+C`.

팀원에게는 이 폴더의 HTML·CSS·JS 파일을 함께 전달하면 된다. 이 서버는 시안 폴더만 제공한다. 저장소 전체나 `fixtures`를 웹 루트로 사용하지 않는다.

## 빠르게 전체 흐름 경험하기

1. 문제 탐색 → 첫 문제 만나보기 → 이 문제 시작하기.
2. 풀이 화면에서 `작성 예시 넣기`로 보고서를 채우거나 직접 작성한다. AI 영역은 예시 대화다.
3. `보고서 저장하고 검산하기`를 누르고 별도 초안 안내를 확인한다.
4. 검산 문장을 선택하고 판단·이유를 입력한다. `내용 수정`을 선택하면 수정문도 입력한다. 자료의 줄을 누르면 근거가 연결된다.
5. `이 문장 검토 저장` 후 제출한다. 한 문장만 검토해도 미검토 안내를 확인한 뒤 제출할 수 있다. 작성 중인 검토가 있으면 먼저 저장해야 한다.
6. 리포트에서 내가 입력한 판단과 원문 근거를 확인한다.
7. 되묻기에서 두 질문에 답한다. `답변 예시 넣기`도 사용할 수 있다.
8. 새 조건을 확인한 뒤 보고서를 수정하거나 판단을 유지한 이유를 쓴다. `수정 예시 넣기`로 화면을 빠르게 경험할 수 있다.
9. 최종 제출 → 최초·최종 비교 → 내 학습으로 돌아간다.

`내 학습`에서 진행 중인 문제를 이어갈 수 있다. 처음부터 다시 보려면 해당 화면의 `처음부터 다시 연습하기`를 사용한다. 이 동작은 이 시안의 브라우저 기록만 초기화한다. 최종 리포트의 `내 작성 기록 보기`에서는 전체 기록을 Markdown 텍스트로 확인하고 선택·복사할 수 있다.

## 화면 구성

| 주소의 해시 | 화면 | 핵심 행동 |
|---|---|---|
| `#explore` | 문제 탐색 | 실제 체험 가능한 문제 1개 선택, 진행 상태 필터 |
| `#detail` | 문제 소개 | 상황·자료·학습 목표·진행 과정 확인 |
| `#workspace` | 분석·보고서 작성 | 자료 열람, 예시 AI 대화, 내 보고서 작성 |
| `#challenge` | 검산 | 문장 판단, 원문 인용, 검토 저장·제출 |
| `#feedback` | 1차 리포트 | 실제 입력 기록·근거 확인, 다음 연습 시작 |
| `#defense` | 되묻기 | 질문 2개에 답하고 생각 설명 |
| `#revise` | 새 조건·보고서 수정 | 최초 보고서를 보며 최종 보고서와 이유 작성 |
| `#final` | 최종 리포트 | 최초·최종 비교, 답변·수정 이유 확인 |
| `#learning` | 내 학습 | 이어하기, 완료한 리포트 다시 보기 |

후속 단계는 필요한 이전 입력·제출을 마쳐야 접근된다. 이 단계 가드는 **UX 시뮬레이션**이며, 서버의 인증·권한·공개 상태 통제를 구현한 것은 아니다.

## 디자인 방향

**차분한 학습 공간. 문제를 고르는 순간부터, 판단을 되짚는 마지막 순간까지 같은 서비스로 느껴지게 한다.**

- 탐색 화면: 학습 목표를 보여주는 큰 제목, 노트·근거 연결 일러스트, 문제 카드와 간단한 학습 과정.
- 풀이 화면: 원본 자료·분석·작성의 역할이 분명한 작업 패널. 검산도 같은 패널 문법을 사용한다.
- 피드백 화면: 점수·순위 대신 내가 남긴 기록과 원문 근거를 중심에 둔다. 다음 행동을 오른쪽 카드로 안내한다.
- 문구: ‘왜 틀렸나요’보다 ‘왜 그렇게 생각했나요’, ‘판단을 바꿔도 근거를 더해 유지해도 좋아요’처럼 설명과 재시도를 돕는다.
- 콘텐츠: 만들지 않은 문제를 실제로 제공하는 것처럼 나열하지 않는다. 현재 과제 1개와 실제 체험 상태만 표시한다.

### 제안 토큰

| 항목 | 값 | 역할 |
|---|---|---|
| 페이지 바탕 | `#F7F8F5` | 장시간 읽어도 차분한 배경 |
| 패널 바탕 | `#FFFFFF` | 읽기·입력 영역 구분 |
| 주 강조 | `#255846` | 브랜드, 주 행동, 선택 상태 |
| 보조 강조 | `#D5E9A7` | 다음 학습 행동·일러스트 강조 |
| 연한 녹색 | `#EAF0E5` | 안내·근거·선택 배경 |
| 기본 글자 / 보조 글자 | `#24342D` / `#647169` | 정보 위계 |
| 경계선 | `#E0E5DD` | 패널과 문서 구분 |
| 새 정보 | `#FFF5DF` | 조건 변경 안내 |
| 글꼴 | OS 한글 산세리프 | 외부 폰트 다운로드 없이 실행 |
| 제목 | 홈 42px, 풀이 25px, 모바일 홈 33px | 탐색과 집중 화면의 밀도 차이 |
| 간격 | 4·8·12·16·24·32·48px 중심 | 공통 배치 리듬 |
| 모서리 | 버튼 8px, 패널 12~16px, 히어로 22px | 친근하되 과하게 둥글지 않게 |

대부분의 정보는 평면 배경과 경계선으로 구분하고, 그림자는 떠 있는 모달·선택된 모바일 탭에 제한한다. 전체 흐름의 화면 진입에는 짧은 전환을 쓰고, 입력·자료 선택 때에는 화면을 다시 흐리게 하지 않는다. 동작 줄이기 설정을 존중한다.

### 반응형과 상태

- 880px 이하: 세 작업 패널을 자료·대화/초안·작성/검토 탭으로 전환한다. 탭 전환에도 입력과 근거는 보존한다.
- 640px 이하: 문제 카드와 비교 문서를 세로로 배치하고, 입력란을 16px로 표시한다.
- 문장 검토는 미검토·작성 중·검토 저장됨·제출됨을 구분한다.
- 최초 보고서, 제출된 검산, 되묻기 답변, 최종 보고서는 각 제출 이후 읽기 전용으로 유지한다.
- 오류는 입력 가까이에 표시한다. 빈 보고서, 누락된 판단·이유·수정문, 미완료 질문, 누락된 최종 수정 이유를 안내한다.
- 모달은 Escape로 닫을 수 있고, 키보드 포커스를 내부에 유지하며 닫은 뒤 이전 위치로 돌려준다.

## 구현 경계

- HTML·CSS·일반 JavaScript로 구성한 독립 시안이다. 실제 `apps/web`, `apps/api`, API 계약, DB migration은 변경하지 않았다.
- 새로 작성한 UI 검토용 가상 상황만 사용한다. 저장소의 public/private fixture를 읽거나 복사하지 않는다.
- 로그인·실제 AI 호출·실제 평가·서버 저장·멀티 기기 동기화·배포는 구현하지 않았다.
- 리포트는 입력한 검토·보고서·답변을 보여준다. 학습 안내와 질문은 미리 작성된 예시다. 정오 판정이나 교육 효과를 검증하지 않는다.
- 자료와 후속 예시는 이 정적 시안의 코드에 포함된다. 실제 비공개 과제 데이터를 같은 방식으로 넣으면 안 된다.
- 작성 내용은 `doezip-design-learning-v1`이라는 독립 localStorage 키에 저장한다. 다른 앱의 저장 데이터는 다루지 않는다. 저장이 차단된 브라우저에서는 탭 종료 후 보존을 보장하지 않는다.
- 예상 30분은 화면에 넣은 가설이며 사용자 테스트로 측정한 값이 아니다.

## 합의할 지점

1. 문제 탐색 화면의 분위기와 문제 카드 밀도가 원하는 학습 플랫폼에 맞는가?
2. 풀이 화면에서 자료·분석·작성을 동시에 보는 구조가 적절한가?
3. 점수 없이 기록·근거·다음 행동을 보여주는 리포트가 이해되는가?

합의한 뒤 화면·토큰·상태 문서를 `docs/design`의 승인 자료로 반영하고, 실제 프론트엔드 공통 컴포넌트로 이식한다. 이 시안 자체를 승인된 디자인으로 간주하지 않는다.
