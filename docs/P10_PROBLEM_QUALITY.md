# P10 문제 품질 고도화

## 목적

AI에게 결과물을 대신 만들어 달라고 요청하는 것보다 제안을 검토하고 자신의 판단으로 채택·보류·거절하는 과정을 더 분명하게 관찰한다. 기존 과제와 제출 기록은 그대로 유지하고, 새 과제와 새 평가 기준은 별도 버전으로 추가한다.

## 새 보고서 과제

`activation-drop-report / activation-drop-v1`은 공개 가상 자료 네 개를 제공한다.

- 전체·플랫폼별 가입 후 7일 활성화 퍼널 CSV
- 온보딩 문구 실험 배정과 결과 JSON
- 고객 문의와 앱 리뷰의 제한된 VOC 표본
- 특정 원인으로 결론 내 달라는 제품 리드 요청과 미수집 지표

사용자는 평균과 세그먼트, 실험 시점과 하락 시점, VOC의 대표성 한계를 대조한다. 경쟁 가설을 비교하고 오늘 실행할 조치, 다음 분석, 판단을 바꿀 조건을 제품 리드용 보고서로 작성한다. 자료는 실제 사용자·기업 데이터가 아닌 가상 공개 자료다.

## 새 구현 과제

`retry-policy-coding / retry-policy-v1`은 결제 요청 재시도 정책을 구현한다. 시작 코드는 모든 5xx를 재시도하는 과도하게 넓은 조건을 포함한다. 공개 QuickJS 테스트는 다음을 실제로 실행한다.

- 429·503과 네트워크 시간 초과의 허용 조건
- 일반 500의 거절
- 최대 시도 횟수
- 멱등성 키 필수 조건
- 입력 객체 보존

AI 코딩 도우미에는 현재 과제 버전과 요구사항을 전달한다. 제안 코드는 자동 적용하지 않으며 사용자가 공개 테스트와 추가 반례로 확인한다. 공개 테스트는 브라우저 실행 기록이고 독립 서버 채점이나 비공개 정답 검증은 아니다.

## 평가 기준 v2

새 learning flow는 `learning-feedback-v2`를 사용한다. 기존 flow의 `learning-feedback-v1`은 보존한다.

- 요청: 문제·맥락·제약·확인 범위를 실제 요청 기록으로 확인
- 검증: 제안과 원자료·요구사항·실행 결과의 대조, 채택하지 않은 제안과 이유 확인
- 개선: 검증 결과가 최종 결과물에 반영됐는지 확인
- 설명: 선택, 대안, 반대 근거, 남은 불확실성과 조건 변경 시 행동 확인

역할 지정, 단계별 지시, 특정 키워드, 대화 횟수와 길이만으로 점수나 AI 의존도를 판정하지 않는다. 테스트 통과도 확인한 범위만 근거로 사용한다.

## 호환성과 제외 범위

- 기존 catalogId, 콘텐츠 version, 제출물과 피드백을 수정하지 않는다.
- Flyway V21은 새 coding suite를 허용하고 이후 생성되는 flow의 평가 prompt 기본값만 v2로 바꾼다.
- local/demo V22는 새 공개 가상 보고서 자료를 추가한다.
- 숨은 테스트, 서버 채점, 다른 언어·다중 파일 실행, SQL·테스트 작성 과제, 기업 문제 빌더는 이번 범위가 아니다.

## 검증 기준

- 공개 카탈로그가 기존 과제와 새 과제 네 개를 함께 반환하고 힌트를 노출하지 않는지 확인
- PostgreSQL 17 Testcontainers에서 새 보고서 자료 네 개, 새 coding workspace와 평가 prompt v2를 확인
- 넓은 5xx 재시도 코드가 공개 경계 테스트에서 실패하고 안전한 조건이 통과하는지 QuickJS로 확인
- OpenAPI enum과 생성 타입의 일치 확인
- 웹 단위 테스트, production build, 전체 API test/build와 Playwright 학습 흐름 확인
