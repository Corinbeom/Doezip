# F04c 검산·평가 화면 스타일 보완

## 범위와 분리
feature/F04c-challenge-ui는 origin/develop에서 분기하고 F05b까지 선행 커밋 11개를 가져왔다. UI 작업 전 기준 HEAD는 147522b다. F05c의 미커밋 AI 어댑터·환경 설정은 가져오지 않았다. 별도 worktree F04c-challenge-ui에서 작업한다.

## 확인한 문제와 수정
- 검산 CSS의 --border/--accent가 승인된 shell에 정의되어 있지 않아 테두리가 사라졌다. 실제 토큰 --line/--green을 사용한다.
- 문장별 카드, 상태 안내, 판단·이유 입력과 원자료 인용을 승인 색상과 여백으로 구분한다. 읽기 전용 입력도 읽을 수 있는 대비를 유지한다.
- 결과가 연결된 뒤에도 남아 있던 “평가 결과는 아직 제공되지 않습니다”를 현재 흐름의 안내로 교체했다.
- 평가 리포트의 영역·기준·인용을 scoped CSS로 구분한다. API/DB/모델/평가 규칙은 변경하지 않는다.

## 검증
실제 API에 연결한 브라우저 검사에서 문장 카드와 입력 테두리를 computed style로 검사하고 저장·제출·새로고침, 320px 가로 넘침을 확인한다. 리포트 UI 검사는 명시적인 테스트 응답으로 조회 경계만 검사하며 실제 AI 호출 성공 검사가 아니다. 최종 실행 결과는 아래에 기록한다.

첫 전체 검사에서 선행 F05b의 결과 검증 테스트가 무작위 루브릭 순서를 가정해 실패했다. 해당 테스트에서 첫 항목 대신 PROMPT 영역을 명시하도록 보완했다. F05c에도 같은 보완이 존재하며 이 브랜치에는 해당 테스트 한 줄만 적용했다. API 구현·검증 규칙은 그대로다.

## 실행 결과
- 웹 lint/typecheck/단위 테스트 74개/build 성공. 마지막 평가 안내 문구 수정 후에도 check:web 재실행 성공.
- API test/build 및 Testcontainers PostgreSQL 60개 성공(실패·skip 없음). 최초 순서 의존 실패와 보완은 위에 별도 기록했다.
- Playwright 전체 37개 성공. 마지막 안내 문구·캡처 변경 후 검산/평가 8개를 재실행해 성공했다.
- 카드/입력 테두리의 computed style, 검토 저장·제출·새로고침·오류 입력 유지, 320px 가로 넘침, 결과 조회/재시도 확인. 캡처도 시각 확인했다. 영역 캡처에는 고정 헤더를 숨기는 촬영 전용 스타일을 사용했다.
- git diff --check 성공. 사용자가 실제 화면 수정도 확인했다. AI 작업과 분리해 커밋·일반 push하며 PR/merge는 수행하지 않는다.

## 현재 사용자 확인용 실행
웹은 이 UI worktree를 localhost:3129에서 실행하고 API는 기존 F05c worktree의 localhost:8299를 사용한다. 기존 F05c DB55529와 사용자 평가/보고서는 보존한다. 웹 실행에는 F05c .env 중 NEXT_PUBLIC_API_BASE_URL 및 Supabase의 공개 설정 두 개만 프로세스 환경으로 전달했다. Gemini 키는 UI worktree에 복사하지 않았다. UI 검증 DB55539/웹3139/API8309는 별도이며 일반 사용자 데이터와 섞지 않는다.

코드 브랜치는 합치지 않았으며 이 연결은 로컬 UI 확인용이다. AI 호출을 다시 실행하지 않았고 실제 평가·복원 성공은 앞선 사용자 수동 확인 기록이다.
