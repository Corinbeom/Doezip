# P05 AI 대화 작업 공간

2026-09-16, `feature/P05-ai-workspace`. 현재 공개 흐름의 UI 품질 변경이 아직 `develop`에 통합되지 않아 `feature/P04-product-quality`의 `2218d44`를 기준으로 분기했다. P04 통합 뒤 이 브랜치의 변경을 검토한다.

## 목적과 범위

보고서와 구현 과제에서 AI 질문 영역이 일반 입력 폼처럼 보이던 문제를 개선한다. API 계약, DB, AI 프롬프트와 결과물 저장 규칙은 변경하지 않는다. AI 답변과 수정안은 사용자의 결과물에 자동 반영하지 않으며, 직접 대조·적용·검증하는 학습 흐름을 유지한다.

## 구현

- 공통 AI 대화 프레임에 AI 코치 헤더, 사용자·AI 메시지 구분, 스크롤 대화 기록과 하단 입력 영역을 제공한다.
- 첫 대화에는 과제에 맞는 질문 예시를 표시한다. Enter는 전송, Shift+Enter는 줄바꿈이며 한글 조합 중 Enter는 전송하지 않는다.
- 응답 생성, 실패, 취소, 다시 확인과 읽기 전용 상태를 대화 안에서 표시한다. 새 메시지가 오면 최근 기록으로 이동한다.
- 보고서 대화는 공개 자료·완료 대화와 선택한 저장 초안의 전달 범위를 접어 확인하게 한다. 기존 opt-in과 저장 완료 조건을 유지한다.
- 구현 대화는 요청과 답변을 한 쌍의 메시지로 표시하고 변경 전·제안 코드를 접어 비교한다. 검토한 수정안만 사용자가 직접 적용할 수 있다.
- 코드 펜스는 HTML로 실행하지 않고 텍스트와 코드 블록으로만 렌더링한다.
- 데스크톱은 보고서와 구현 과제 모두 왼쪽에 결과물, 오른쪽에 자료·AI를 둔다. 모바일은 `내 결과물` → `자료` → `AI 대화` 순서로 전환한다. 바깥 패널은 고정하고 대화 기록만 스크롤하며, 패널을 전환해도 작성 중인 코드와 질문은 보존한다.
- 흐름 안의 보고서 카드는 작업 영역 높이를 채우고 입력창이 남은 공간을 사용한다. 고정 픽셀 높이와 마크다운 편집·미리보기는 이번 범위에 포함하지 않는다.
- 데스크톱 작업 영역은 `680px~860px` 범위에서 화면에 맞춰 늘어난다. AI 대화 기록이 남은 공간을 사용하고 입력창은 하단에 유지한다. 질문 예시는 접이식이며 첫 요청 뒤 자동으로 접힌다.

## 검증

- `npm run check:web`: lint, typecheck, Vitest 23개 파일·105개 테스트, Next production build 통과.
- `npm run check`: OpenAPI와 공개 fixture 31개, 웹 검사, API JUnit·Testcontainers PostgreSQL·build 통과. 첫 Playwright 실행은 새 대화 헤더 때문에 기존 `header` 선택자가 모호해져 48/49에서 실패했다. 제품 헤더를 `banner` 역할로 선택하도록 회귀 테스트를 수정했다.
- 수정 후 학습 흐름 Playwright 7개 통과.
- 최종 `npm run test:e2e`: 테스트 인증 공개값을 빌드 단계부터 적용한 실제 웹·API·PostgreSQL 환경에서 Playwright 49개 통과. 보고서/구현 대화, 320px 가로 넘침, 모바일 패널 전환, 저장 복원, 실패·중지·제출 잠금을 포함한다.
- API 테스트 종료 시 Testcontainers가 내려간 뒤 평가 스케줄러의 연결 경고가 출력됐지만 Gradle은 `BUILD SUCCESSFUL`로 완료됐다.

실제 Gemini 호출과 새 Google 로그인을 이번 변경 검증에서 추가 실행하지 않았다. 로컬 3189의 기존 Supabase 세션이 만료되어 사용자가 다시 로그인한 뒤 실제 대화의 최종 시각 확인이 필요하다. `.env`와 실제 키는 Git 대상이 아니다.
