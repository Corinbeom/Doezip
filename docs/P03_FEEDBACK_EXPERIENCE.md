# P03 힌트·근거·피드백 경험

## 목적

P02의 단계형 수행 흐름은 유지하면서 사용자가 지금 무엇을 보고 무엇을 해야 하는지 더 빠르게 파악하게 한다. 이번 작업은 훈련 힌트, 원자료 연결, 평가 결과 읽기 방식을 다듬는다. 평가 계약·DB·AI 호출 방식은 변경하지 않는다.

## 사용자 경험

### 훈련 힌트

- 과제 유형에 맞는 세 주제를 카드로 보여 주고 선택한 한 주제만 펼친다.
- 이미 연 힌트는 다시 자유롭게 전환할 수 있다.
- 열람 수는 학습 진행 안내일 뿐 평가 점수나 역량 증거가 아니다.
- 모의 전형에는 힌트를 노출하지 않는다.

### 원자료 연결

- 숫자 필드에 줄 범위를 외워 입력하는 대신 실제 자료를 읽고 시작 줄을 누른다.
- 한 줄만 연결하거나, 뒤의 줄을 하나 더 눌러 연속 범위를 선택한다.
- 연결 전 정확한 원문을 미리 보고, 연결 뒤에는 자료명·줄 범위를 확인하고 삭제할 수 있다.
- 서버의 소유권·범위·최대 8개 검증은 그대로 적용한다.

### 피드백 읽기

- 요청 구체화, 근거 확인, 결과물 개선, 판단 설명 순서로 한 항목씩 집중해서 본다.
- 집중 카드에는 관찰, 평가에 사용된 정확한 원문, 다음 행동을 함께 표시한다.
- 원문 연결 메타데이터가 JSON으로 저장된 경우 식별자 대신 사용자가 선택한 `quote`만 표시한다.
- 이전·다음 및 번호 이동을 제공하고 reduced-motion 설정에서는 부드러운 스크롤을 사용하지 않는다.
- 우선 연습할 항목을 별도 카드로 보여 준다.
- 전체 피드백 기록은 같은 화면 아래에 계속 남겨 사용자가 언제든 네 항목을 한 번에 다시 확인할 수 있다.

## 경계

- 집중 보기와 전체 기록은 이미 저장된 같은 공개 평가 결과를 표시한다. 별도 평가나 가짜 성공 응답을 만들지 않는다.
- E2E의 성공 응답은 UI 계약 검사용 공개 가상 데이터이며 실제 Gemini 평가 성공으로 보고하지 않는다.
- 실제 사용자 보고서와 인용은 HTML로 실행하지 않는다.
- 캐릭터·브랜드 심볼과 최종 일러스트레이션은 이번 범위가 아니다.

## 검증

- 웹 lint, typecheck, unit test, production build
- API test/build 회귀
- PostgreSQL·실제 API를 사용하는 네 과제 조합 E2E
- 힌트의 훈련/모의 전형 경계, 실제 원문 선택, 집중 피드백 이동, 전체 기록, 모바일과 reduced-motion
- OpenAPI 생성물 변경 없음
